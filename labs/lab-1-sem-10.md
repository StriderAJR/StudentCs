# Лабораторная работа 10. Игровой сервер

## Сложность

4 / 5

## Темы

Списки, словари, класс, объект, инкапсуляция.

## Задание

Вы разрабатываете сервер многопользовательской игры.

Во время работы сервера игроки могут подключаться, отключаться, изменять свои характеристики и выполнять различные действия.

Для каждого игрока необходимо хранить информацию, достаточную для работы сервера. Самостоятельно определите набор необходимых характеристик.

Программа должна поддерживать следующие возможности:

- подключение нового игрока;
- отключение игрока;
- вывод списка всех игроков;
- поиск игрока по логину;
- изменение характеристик игрока;
- отображение информации о выбранном игроке.

При проектировании программы самостоятельно определите, какие коллекции следует использовать для хранения данных.

После реализации программы оцените удобство выполнения различных операций. Если некоторые действия оказались слишком сложными или требуют перебора большого количества объектов, попробуйте изменить способ хранения данных.

## Исследование производительности

После завершения программы сравните скорость поиска игрока по логину при использовании различных коллекций.

Для этого:

1. Загрузите в программу файл, содержащий несколько тысяч игроков.
2. Реализуйте поиск игрока по логину с использованием списка.
3. Реализуйте поиск того же игрока с использованием словаря.
4. Замерьте время выполнения каждого варианта.

Для измерения времени можно воспользоваться классом `Stopwatch`.

Например:

```csharp
using System.Diagnostics;

var stopwatch = Stopwatch.StartNew();

// Здесь выполняется поиск игрока.

stopwatch.Stop();

Console.WriteLine($"Время поиска: {stopwatch.Elapsed.TotalMilliseconds} мс");
```

Для получения более точного результата рекомендуется выполнить поиск одного и того же игрока несколько сотен или тысяч раз.

Например:

```csharp
for (var i = 0; i < 10000; i++)
{
    // Поиск игрока.
}
```

После выполнения эксперимента сравните полученные результаты и попробуйте объяснить, почему разные коллекции показали разную скорость поиска.

### Генерация тестовой базы игроков

Во время разработки удобно работать с небольшим количеством игроков. Однако для сравнения различных способов хранения данных потребуется база, содержащая несколько тысяч записей.

Вы можете самостоятельно заполнить файл данными или воспользоваться небольшой программой-генератором.

Например:

```csharp
using System;
using System.IO;

internal class Program
{
    private static readonly Random Random = new();

    private static void Main()
    {
        using var writer = new StreamWriter("players.txt");

        for (var i = 1; i <= 10000; i++)
        {
            var login = $"Player{i:D5}";
            var level = Random.Next(1, 101);
            var gold = Random.Next(0, 100000);
            var x = Random.Next(0, 500);
            var y = Random.Next(0, 500);

            writer.WriteLine($"{login};{level};{gold};{x};{y}");
        }

        Console.WriteLine("Файл успешно создан.");
    }
}
```

Полученный файл может иметь следующий вид:

```text
Player00001;18;5340;42;91
Player00002;67;19850;315;128
Player00003;5;420;17;256
Player00004;91;78000;482;19
...
```

При запуске основной программы рекомендуется автоматически загружать информацию обо всех игроках из этого файла.

Это позволит проверить работу программы на большом объёме данных и сравнить удобство использования различных коллекций.
