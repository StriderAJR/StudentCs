# Лабораторная работа 9. Персонаж RPG

## Сложность

3 / 5

## Темы

Инкапсуляция, поле, свойство, конструктор, readonly-поля, исключения, класс, объект.

## Задание

Вы разрабатываете систему управления персонажем для компьютерной RPG.

Каждый персонаж обладает набором характеристик. Самостоятельно определите, какие данные необходимо хранить. Например:

- имя;
- класс персонажа;
- уровень;
- количество опыта;
- здоровье;
- максимальное здоровье;
- золото;
- сила;
- защита;
- другие характеристики.

Программа должна позволять выполнять различные действия с персонажем. Например:

- получать урон;
- восстанавливать здоровье;
- получать опыт;
- повышать уровень;
- получать золото;
- тратить золото;
- выводить текущую информацию о персонаже.

Самостоятельно определите, какие данные должны изменяться свободно, а какие должны изменяться только определённым способом.

После реализации программы попробуйте намеренно привести персонажа в некорректное состояние. Например:

- сделать количество здоровья отрицательным;
- установить здоровье больше максимального;
- уменьшить уровень;
- потратить больше золота, чем имеется;
- начислить отрицательное количество опыта;
- выполнить другие действия, которые нарушают логику игры.

После этого измените устройство класса так, чтобы подобные ситуации стали невозможны.

Если некоторую операцию невозможно выполнить, программа должна сообщить об ошибке.

### Один из возможных вариантов работы программы

```text
1 - Показать информацию о персонаже
2 - Получить урон
3 - Восстановить здоровье
4 - Получить опыт
5 - Получить золото
6 - Потратить золото
7 - Повысить уровень
0 - Выход
```

Каждая команда может запрашивать необходимые данные.

Например:

```text
Введите количество полученного урона:
25
```

или

```text
Введите количество полученного золота:
100
```

---

### Подумайте, кто должен отвечать за корректность данных

Например, какой вариант кажется более безопасным?

```csharp
player.Health -= damage;
```

или

```csharp
player.TakeDamage(damage);
```

Во втором случае именно объект персонажа самостоятельно решает, как правильно изменить своё состояние.

---

### Попробуйте испортить персонажа

После того как программа будет готова, попробуйте выполнить действия, которые не имеют смысла.

Например:

- установить отрицательное количество здоровья;
- установить здоровье больше максимального;
- начислить отрицательное количество опыта;
- уменьшить количество золота ниже нуля.

Если сделать это удалось, значит объект недостаточно защищает своё состояние.

---

### Если выполнение некоторой операции невозможно

Например:

- игрок пытается потратить больше золота, чем имеет;
- количество здоровья становится отрицательным;
- в метод передано отрицательное количество опыта.

Подумайте, должна ли программа молча продолжать работу или лучше сразу сообщить об ошибке.

В C# для подобных ситуаций используются исключения.
