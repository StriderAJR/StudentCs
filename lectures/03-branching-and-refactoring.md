# Лекция 3: ветвления и принятие решений

## Введение

До этого программа выполняла команды одну за другой. Но мониторингу сервера мало вывести числа — ему нужно сделать вывод: сервер готов, перегружен или выключен.

Ветвление позволяет программе выбрать разные действия в зависимости от условия.

## Условие и `if`

``` csharp
int players = 75;
int limit = 100;

if (players < limit)
{
    Console.WriteLine("Есть свободные места");
}
```

Выражение `players < limit` имеет тип `bool`. Если оно равно `true`, выполняется блок в фигурных скобках. Если `false`, этот блок пропускается.

## Два варианта: `if else`

``` csharp
bool isOnline = true;

if (isOnline)
{
    Console.WriteLine("Сервер доступен");
}
else
{
    Console.WriteLine("Сервер выключен");
}
```

`else` выполняется тогда, когда условие `if` оказалось ложным.

## Несколько вариантов

``` csharp
int players = 110;
int limit = 100;
bool isOnline = true;

if (!isOnline)
{
    Console.WriteLine("Запуск невозможен: сервер выключен");
}
else if (players > limit)
{
    Console.WriteLine("Запуск невозможен: превышен лимит игроков");
}
else if (players > limit - 10)
{
    Console.WriteLine("Сервер можно запустить, но нужна проверка");
}
else
{
    Console.WriteLine("Сервер готов к запуску");
}
```

Проверки выполняются сверху вниз. Как только найдено истинное условие, остальные ветки этой цепочки пропускаются. Поэтому порядок проверок важен.

## `switch` для известных вариантов

``` csharp
string status = "warning";

switch (status)
{
    case "online":
        Console.WriteLine("Сервер работает");
        break;
    case "warning":
        Console.WriteLine("Нужна проверка");
        break;
    default:
        Console.WriteLine("Сервер недоступен");
        break;
}
```

`switch` наглядно показывает список известных состояний. Для произвольных сравнений удобнее оставить `if`.

## Условия должны объяснять решение

Плохой вариант:

``` csharp
if (a && b && !c || d)
{
    Console.WriteLine("OK");
}
```

Непонятно, что такое `a`, `b`, `c` и `d`. Лучше дать условиям имена:

``` csharp
bool isOnline = true;
bool hasFreeSlots = true;
bool hasCriticalError = false;

if (isOnline && hasFreeSlots && !hasCriticalError)
{
    Console.WriteLine("Сервер готов");
}
```

Код должен сообщать не только компьютеру, но и человеку, почему принято решение.

## Рефакторинг

Рефакторинг — это изменение внутреннего устройства кода без изменения его поведения. Например, сложному условию можно дать отдельное имя:

``` csharp
bool canStart = isOnline && hasFreeSlots && !hasCriticalError;

if (canStart)
{
    Console.WriteLine("Сервер готов");
}
```

Хороший рефакторинг делает код понятнее. Если после «улучшения» стало труднее понять программу, это было не улучшение, а перестановка мебели.

## Ветвление внутри метода

Метод может скрыть детали проверки и вернуть готовое решение:

``` csharp
static string GetServerVerdict(bool isOnline, int players, int limit)
{
    if (!isOnline)
    {
        return "Сервер выключен";
    }

    if (players >= limit)
    {
        return "Сервер переполнен";
    }

    return "Сервер готов";
}
```

Теперь основной код не обязан знать порядок проверок. Метод отвечает за вердикт, вызывающий код — за то, что делать с результатом.

## Итог

`if` выбирает блок по логическому условию, `else` обрабатывает альтернативу, `else if` позволяет проверить несколько вариантов, а `switch` удобно использовать для набора известных состояний. Условия лучше называть понятными переменными, а порядок проверок нужно выбирать осознанно.
