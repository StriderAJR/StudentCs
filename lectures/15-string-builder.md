# Лекция 15: `StringBuilder` и большие тексты

## Почему `+` может быть дорогим

Строки неизменяемы. В выражении с конкатенацией создаётся новый строковый объект.

``` csharp
string report = "";

for (int i = 1; i <= 3; i++)
{
    report += $"Игрок {i}\n";
}
```

На каждой итерации старая строка копируется в новый объект вместе с добавленным текстом. Для трёх строк это незаметно, для тысяч — уже лишние выделения памяти и копирования.

## `StringBuilder`

``` csharp
StringBuilder builder = new StringBuilder();

for (int i = 1; i <= 3; i++)
{
    builder.AppendLine($"Игрок {i}");
}

string report = builder.ToString();
```

`StringBuilder` хранит изменяемый буфер и расширяет его по мере необходимости. Финальная строка создаётся один раз при `ToString`.

![StringBuilder и его буфер в памяти](../img/lectures/09/shared-object.png)

`StringBuilder` уменьшает количество промежуточных строк, но не является универсально «более быстрым». Для маленьких сообщений обычная интерполяция проще и вполне достаточна.

## Как сравнивать производительность

Сравнивать нужно одинаковые задачи и достаточно большое число повторений. Один запуск ничего не доказывает: влияют прогрев JIT, сборка мусора и состояние компьютера.

``` csharp
Stopwatch timer = Stopwatch.StartNew();
StringBuilder builder = new StringBuilder();

for (int i = 0; i < 100_000; i++)
{
    builder.Append(i);
}

timer.Stop();
Console.WriteLine(timer.ElapsedMilliseconds);
```

Таймер измеряет время, но не объясняет его причину. Для серьёзных измерений используют BenchmarkDotNet, а результат повторяют несколько раз.

## Итог

`StringBuilder` полезен при последовательной сборке большого текста. Выбирайте его осознанно и проверяйте производительность измерением, а не ощущением.
