# Лекция 14: полиморфизм и виртуальные методы

## Один вызов — разные действия

Полиморфизм позволяет работать с объектами через общий тип, оставляя каждому объекту собственную реализацию.

``` csharp
class WorldObject
{
    public virtual void Interact()
    {
        Console.WriteLine("Обычное взаимодействие");
    }
}

class Chest : WorldObject
{
    public override void Interact()
    {
        Console.WriteLine("Сундук открыт");
    }
}

WorldObject target = new Chest();
target.Interact(); // Сундук открыт
```

Тип переменной `WorldObject` задаёт доступный интерфейс, но реальный объект в куче — `Chest`. Поэтому вызывается переопределённый метод.

Это позднее связывание: окончательная реализация выбирается во время выполнения. Базовый метод задаёт общий контракт, а наследник обязан сохранить смысл этого контракта, меняя только конкретное поведение.

Это называется поздним связыванием: окончательный выбор реализации происходит во время выполнения. Если метод не объявлен `virtual`, а в наследнике просто написать метод с тем же именем, полиморфного вызова не получится.

## Схема ссылок

![Полиморфная ссылка на объект](../img/lectures/09/shared-object.png)

Если хранить несколько объектов в массиве базового типа, не нужны проверки «если это сундук, вызвать такой метод».

``` csharp
WorldObject[] objects = { new Chest(), new WorldObject() };

foreach (WorldObject worldObject in objects)
{
    worldObject.Interact();
}
```

Добавление `Door : WorldObject` с собственной реализацией `Interact` не требует переписывать этот цикл. В этом и состоит практическая ценность полиморфизма: общий алгоритм не знает всех будущих типов.

Такой цикл открыт для расширения. Добавление `Door : WorldObject` с собственной реализацией `Interact` не требует переписывать цикл.

## Итог

Виртуальный метод выбирается по реальному типу объекта во время выполнения. Полиморфизм позволяет расширять игру новыми объектами без переписывания общего цикла взаимодействия.
