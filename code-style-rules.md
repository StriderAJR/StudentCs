# Правила оформления кода

## Блоки кода и форматирование ветвлений

Не смешивать скобочные и бесскобочные блоки. Использовать либо всегда скобки, либо всегда бесскобочный стиль. Вложенный if внутри else оформлять с табуляцией или со скобками. Однострочные конструкции допустимы только в виде `else if`.

### Правильные варианты

```csharp
// вариант 2
if (...)
{
    ...
}
else
{
    if (...) ...
    else ...
}

// вариант 3
if (...) ...
else if (...) ...
else ...
```

### Плохой вариант

```csharp
if (...) ...
else
  if (...) ...
  else ...
```

## Именование переменных

Использовать говорящие названия. Однобуквенные имена — только для стандартных случаев: `i, j, k` — счётчики, `c` — символ, `n, m` — размеры.

Неправильные примеры:

* `string number` — вводит в заблуждение, т.к. это строка
* `int c` — зарезервированное типичное имя для символа
* `int[] digit` — название в единственном числе, хотя массив

Правильные варианты:

* `numberStr`, `studentCount`, `currentDeposit`
* массивы во множественном числе: `digits`, `numbers`

## Возврат булевых значений

Не возвращать `true/false` через тернарный оператор. Сразу возвращать условие:

```csharp
return month >= 1 && month <= 12;
```

## Лишние переменные

Не создавать переменные только ради `return`.

```csharp
return 0.5 * Math.Asin((distance * g) / (v * v));
```

## Магические числа

Использовать константы или переменные с понятными именами.

```csharp
float g = 9.8;
return 0.5 * Math.Asin((g * distance) / (v * v));
```

## Комментарии в коде

Не оставлять TODO и пустые документационные блоки.

## Вложенные методы

Не использовать вложенные функции. Каждый метод — на верхнем уровне класса.

## Типы циклов

Бесконечные циклы — через `while(true)`, а не `for(;;)`.

## Область видимости переменных

Объявлять переменную максимально близко к месту использования.

## Работа со строками

При разбиении строки давать частям говорящие имена.

```csharp
var parts = userInput.Split();
var sum = double.Parse(parts[0]);
var interestRate = double.Parse(parts[1]);
var monthCount = double.Parse(parts[2]);
```

## Избегать повторяемости вычислений

Использовать временные переменные для повторяющихся выражений.

## Отказ от лишних веток else при return

```csharp
if (cond) return "a";
if (cond2) return "b";
return "c";
```

## Избегание дублирования кода

Выносить повторяющиеся операции в отдельные методы.

```csharp
double GetDistanceBetweenPoints(double x1, double y1, double x2, double y2)
{
    return Math.Sqrt((x2 - x1)*(x2 - x1) + (y2 - y1)*(y2 - y1));
}
```

## Логическое разбиение программы на методы

Разбивать «полотна кода» на маленькие функции. Основная логика читается сверху вниз.

## Именование переменных

Имя должно отражать тип данных и назначение.

## Запрет абсолютных путей

Использовать относительные пути:

```csharp
File.ReadAllLines("./example.txt");
```

## Разбор реального примера

Исправления включают: относительные пути, корректное именование переменных, разбиение на методы, отказ от вложенных условий, устранение дублирования.

## Рекомендации по построению проектов

Методы применяются не только для устранения дублирования, но и для логического разделения этапов программы.

## Пример улучшенной структуры:

* Main содержит только высокоуровневую логику
* каждая операция вынесена в отдельный метод
* проверка корректности ввода вынесена в отдельный метод
* операции оформлены через switch

```csharp
public static void Main()
{
    int num1 = ReadNumber().Value;
    int? num2 = ReadNumber(true);
    string operation = ReadOperation();

    double result = operation switch
    {
        "+" => num1 + num2.Value,
        "-" => num1 - num2.Value,
        "*" => num1 * num2.Value,
        "/" => num1 / num2.Value,
        "!" => Factorial(num1),
        "log" => Math.Log(num1, num2.Value),
        "dsum" => GetDigitsSum(num1),
        _ => 0,
    };

    Console.WriteLine(result);
}
```
